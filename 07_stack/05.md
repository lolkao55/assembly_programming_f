# 05.asm — 64-bit push and pop

This program demonstrates the stack's last-in, first-out behavior with two 64-bit values. `RSP` points to the top of the stack, which grows toward lower memory addresses. Each `push`/`pop` in this program changes `RSP` by 8 bytes.

## Execution and stack changes

| Instruction(s) | Effect on the stack | GDB observation |
|---|---|---|
| Load `0x1122334455667788` into `RAX` and `0x1234` into `RBX` | Register assignments only; no stack change. | Initial `RSP` was `0x7fffffffde70`. |
| `push rax` | Decreases `RSP` by 8, then stores `RAX` at the new top. | `RSP: 0x7fffffffde70 -> 0x7fffffffde68`; top value: `0x1122334455667788`. |
| `push rbx` | Decreases `RSP` by another 8, then stores `RBX` above the previous value. | `RSP: 0x7fffffffde68 -> 0x7fffffffde60`; top value: `0x1234`, followed by the saved `RAX` value at `0x7fffffffde68`. |
| `nop` | No operation; the stack is unchanged. | `RSP` remains `0x7fffffffde60`. |
| `pop rbx` | Copies the top value into `RBX`, then increases `RSP` by 8. | `RBX = 0x1234`; `RSP: 0x7fffffffde60 -> 0x7fffffffde68`. The saved `RAX` value is now on top. |
| `pop rax` | Copies the next value into `RAX`, then increases `RSP` by 8. | `RAX = 0x1122334455667788`; `RSP: 0x7fffffffde68 -> 0x7fffffffde70`, its initial value. |
| Exit syscall | `RAX` is set to `60`, `RDI` to `0`, then `syscall` exits. It does not push or pop stack data. | The program exited normally with status 0. |

## What this demonstrates

Although `RAX` was pushed first, it is popped second: the most recently pushed value (`RBX`) is the first one removed. Both registers regain the values they had before the pushes, and the two pops balance the two pushes so `RSP` returns to its starting position. A pop advances the pointer; it does not need to erase the old bytes in memory. The address values above use the initial `RSP` observed in your run; they can vary between runs.

**Run observation:** Running the existing `./05` executable printed no output and exited with status 0.
