# 02.asm
- The main function invokes the work function through the call method.
- Call implicitly pushes the caller's next instruction memory address(mov rax,60) to the stack and then pushes the callee's  memory address.
- This is clearly shown when rsp calue decrements after **"call work"** instruction execution
- We then step into the *work* function
## Inside *work* function
- First thing is to save the base pointer's current values which point to caller's function.Why?We save the caller's stack frame so that the callee function does not override the variables stored there.
- Then we move the current address of the stack pointer to rbp.rbp is now used as anchor or the start of a new stack frame that can be used by the work function
- The pointer is decremented by 16 bytes to create space for the variables that will be stored there and to avoid having rsp point towards the wrong values
- **Interesting point for me:** The two pointers actually point towards the stack.I initially thought rsp was the only register involved with the stack so I was confused  why it was being decremented
- Two variables,100 and 200 are created by offsetting rbp.These values are copied into rax and rbx registers.
- mov rsp,rbp:The memory address of the stack frame that holds the caller function address is copied from rbp to rsp.
- The address in the stack is popped and placed in rbp and then **ret** implicitly pops the next instruction that was to be executed before the **work** function was called
