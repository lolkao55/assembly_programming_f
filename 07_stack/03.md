# 03.asm — `call` and `ret`

This 64-bit program starts with the value `10` in `RAX`, calls `calculate`, and exits after the function returns. Its only stack data is the return address created by `call`; it does not create a stack frame or store local variables.

## Execution and stack changes

| Instruction(s) | What happens | Stack effect |
|---|---|---|
| `mov rax, 10` | Sets `RAX` to `10`. | None. The initial `RSP` in this run is `0x7fffffffde70`. |
| `call calculate` | Saves the address of the instruction after the call (`after_call`/`nop`) and transfers execution to `calculate`. | Pushes an 8-byte return address: `RSP` changes from `0x7fffffffde70` to `0x7fffffffde68`. |
| `add rax, 5` | Adds 5 to `RAX`, making it `15`. | None; `RSP` remains `0x7fffffffde68`. |
| `ret` | Pops the saved return address into the instruction pointer, so execution resumes at `after_call`. | `RSP` increases by 8, returning to `0x7fffffffde70`. |
| `nop` at `after_call` | Does nothing. `RAX` still contains `15`. | None. |
| Exit syscall | Sets `RAX` to `60` (Linux x86-64 exit syscall number), sets `RDI` to `0` (exit status), and invokes `syscall`. | No explicit push or pop; `RSP` remains at its starting value until the process exits. |

## Key observation

`call` pushes the return address, not the function's address. `calculate` changes `RAX` but does not touch the stack. `ret` uses the address saved by `call` to resume execution and balances that stack change, so `RSP` is back where it started. The stack addresses above are an example from the observed run and can vary between runs.
