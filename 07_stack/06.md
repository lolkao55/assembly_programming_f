# 06.asm — 32-bit push and pop

This is the 32-bit counterpart to `05.asm`. It demonstrates last-in, first-out behavior using `EAX` and `EBX`. In 32-bit mode, `ESP` is the stack pointer and each pushed value occupies 4 bytes; the stack grows toward lower memory addresses.
.

## Execution and stack changes

| Instruction(s) | Effect on the stack | GDB observation |
|---|---|---|
| Load `0x11223344` into `EAX` and `0x1234` into `EBX` | Register assignments only; no stack change. | Initial `ESP` was `0xffffcfa0`. |
| `push eax` | Decreases `ESP` by 4, then stores `EAX` at the new top. | `ESP: 0xffffcfa0 -> 0xffffcf9c`; top value: `0x11223344`. |
| `push ebx` | Decreases `ESP` by another 4, then stores `EBX` above the previous value. | `ESP: 0xffffcf9c -> 0xffffcf98`; top value: `0x1234`, followed by `0x11223344` at `0xffffcf9c`. |
| `nop` | No operation; the stack is unchanged. | `ESP` remains `0xffffcf98`. |
| `pop ebx` | Copies the top value into `EBX`, then increases `ESP` by 4. | `EBX = 0x1234`; `ESP: 0xffffcf98 -> 0xffffcf9c`. |
| `pop eax` | Copies the next value into `EAX`, then increases `ESP` by 4. | `EAX = 0x11223344`; `ESP: 0xffffcf9c -> 0xffffcfa0`, its initial value. |
| Exit syscall | `EAX` is set to `1`, `EBX` to `0`, then `int 0x80` exits. It does not push or pop stack data. | The program exited normally with status 0. |

## What this demonstrates

The value pushed last (`EBX`) is popped first. After both pops, the registers contain their original values and `ESP` is back where it started. The existing bytes are not erased when popped; moving `ESP` marks that stack space as available again. The addresses above are the values observed in this GDB run and can vary between runs.

**Run observation:** Running the existing `./06` executable printed no output and exited with status 0.
